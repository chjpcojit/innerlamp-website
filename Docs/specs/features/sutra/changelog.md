# Changelog — sutra Spec

Tracks version history for `requirements.md`, `design.md`, and `tasks.md` in this folder. All three
files share one changelog since they change together as one spec unit. Newest version first.

## v1.0 (initial) (2026-10-16)

- `requirements.md`: first spec of the feature on the website, written retroactively from the running code (read 2026-10-16: the list with tradition + "Nhật tụng" (Daily chanting) chips, `?page=` normalisation and past-the-end redirect; the sutra page with the version links, table of contents derived from the loaded lines, one-chapter reader, A−/A+ on `settings.font`, simulated `SutraPlayer`, local dark toggle, source line, related texts of the tradition; the fixed verse lines on `/` and `/lunar/day`) and prospectively for the rest of product v1.0. Header `Product spec` @ v1.0, `Contract` openapi @ 3e1c415 (tag Sutras), `Implements` every ID whose Website column is not `n/a` (FR-STR-012 and NFR-STR-03 are not for the website). 45 criteria, each tagged with its ID or `(platform)`.
- `design.md`: new — Layers & components table, navigation, Step-by-step Flow for the list (normalise → read one page), the sutra page (sutra ∥ other texts) and the reading view (choose version and section → first lines of the section → load more through a new `/api/sutras/[id]/lines` → font size), the quote-of-the-day rule, i18n add / change / delete table. Platform decisions: the reading view is its own route `/library/sutras/[slug]/read`; chapter and version in the URL (`?part=`, `?translation=`); search is a `GET` form; `?topic=` / `?max=` / `?q=` replace `?filter=`; the section is cut from the backend page that holds `start_n`; the quote is computed after mount from a bundled file.
- `tasks.md`: new — 6 Phases; `[x]` only for parts checked in code and matching product. Vector tasks for BR-STR-05 (`sutra-default-version.json`) and BR-STR-10 (`sutra-daily-quote.json`); none for `sutra-browse.json` / `sutra-search-match.json` because ordering, filtering and matching are the backend's.
- Product spec / contract: adopt product v1.0 (§4.2 Website column; §3.6 rows FR-STR-001, FR-STR-005, FR-STR-007, BR-STR-10). Contract openapi @ 3e1c415 (the search term `q` and `max_minutes` are already in it).
- Drift from product (for `ba-writer` to see in the Website column): the card and page title follow the site locale (BR-STR-05); the opening version does not order chant / meaning / poem (BR-STR-05); tradition and daily chips only, no purposes, no duration chips, no search (BR-STR-03, BR-STR-04, FR-STR-002, FR-STR-003); no kind label, citation code or daily mark on the card, duration reads "{N} phút tụng" (BR-STR-01, BR-STR-08); the licence is shown as the raw code and `license_note` is not shown (BR-STR-07); no unreviewed notice (BR-STR-07); linked Buddhas and Bodhisattvas not listed (BR-STR-09, FR-STR-008); simulated player (BR-STR-12); local dark toggle and three font sizes (BR-STR-11); up to 20 × 500 lines loaded before the page renders (NFR-STR-01); table of contents built from the loaded lines, not from the contract `sections`; error state without retry and one empty message for every cause (FR-STR-011); fixed verse lines chosen by lunar day + month (BR-STR-10).
